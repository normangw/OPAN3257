Window functions: one step beyond GROUP BY

GROUP BY collapses rows into one per group. Window functions let you rank or compare rows without collapsing them: think "each order, plus that customer's rank by spend." 

SELECT
    customer_id,
    order_id,
    order_total,
    RANK() OVER (PARTITION BY customer_id ORDER BY order_total DESC) AS spend_rank
FROM orders;

Try adapting this in the sandbox against the seeded orders table.

What's under the hood: indexes & query plans

SQLite decides how it will run a query before it runs it. That decision is called the query plan, and you can see it directly: 

EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE customer_id = 3;

Without an index, that plan reads SCAN orders: check every row. Add one, and it flips to SEARCH orders USING INDEX idx_customer: jump straight to the matching rows. 

CREATE INDEX idx_customer ON orders(customer_id);

DuckDB over real files, not toy tables

DuckDB queries CSV or Parquet files directly, with no import step. That's what "warehouse-grade" means in practice, and it's the pattern behind the NYC TLC trip data and the course's Data Import Bootcamp. 

-- millions of rows, zero installation
SELECT
    date_trunc('month', pickup_datetime) AS month,
    COUNT(*) AS trips,
    AVG(trip_distance) AS avg_miles
FROM read_parquet('nyc_taxi_2024.parquet')
GROUP BY 1
ORDER BY 1;
