Window functions: one step beyond GROUP BY

GROUP BY collapses rows into one per group. Window functions let you rank or compare rows without collapsing them — e.g. "each order, plus that customer's rank by spend." 

SELECT
    customer_id,
    order_id,
    order_total,
    RANK() OVER (PARTITION BY customer_id ORDER BY order_total DESC) AS spend_rank
FROM orders;

Try adapting this in the sandbox against the seeded orders table.

What's under the hood: indexes & query plans

An index is a lookup structure that lets the database skip scanning every row — the same reason a book's index beats reading page by page. In SQLite, you can see how a query will actually run with: 

EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE customer_id = 3;

Once you add CREATE INDEX idx_customer ON orders(customer_id);, re-run the plan and compare.

DuckDB over real files, not toy tables

DuckDB can query CSV or Parquet files directly — no import step — which is what makes it "warehouse-grade." This is the pattern behind the NYC TLC trip data and the course's Data Import Bootcamp. 

-- millions of rows, zero installation
SELECT
    date_trunc('month', pickup_datetime) AS month,
    COUNT(*) AS trips,
    AVG(trip_distance) AS avg_miles
FROM read_parquet('nyc_taxi_2024.parquet')
GROUP BY 1
ORDER BY 1;
